Step 7: Extract authorities (roles)
// JwtAuthenticationConverter in SecurityConfig
public JwtAuthenticationConverter jwtAuthenticationConverter() {
    JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
    
    converter.setJwtGrantedAuthoritiesConverter(jwt -> {
        // Get roles from realm_access
        Map<String, Object> realmAccess = jwt.getClaim("realm_access");
        List<String> roles = (List<String>) realmAccess.get("roles");
        
        // Convert to GrantedAuthority
        return roles.stream()
            .map(role -> new SimpleGrantedAuthority("ROLE_" + role))
            .collect(Collectors.toList());
    });
    
    return converter;
}

Step 8: Create Authentication object
// Spring Security creates Authentication
Authentication auth = new JwtAuthenticationToken(
    jwt,
    authorities,  // [ROLE_CUSTOMER]
    jwt.getSubject()  // Keycloak user ID
);

// Set in SecurityContext
SecurityContextHolder.getContext().setAuthentication(auth);

Step 9: Check @PreAuthorize (if exists)
@PreAuthorize("hasRole('ADMIN')")
public void adminOnlyMethod() {
    // This will fail for CUSTOMER role
}

Step 10: Execute service method
@GetMapping("/me")
public ResponseEntity<ApiResponse<UserResponse>> getCurrentUser() {
    // Get user ID from JWT
    String keycloakId = getCurrentKeycloakUserId();
    
    // Query database
    User user = userRepository.findByKeycloakId(keycloakId)
        .orElseThrow(() -> new ResourceNotFoundException("User not found"));
    
    return ResponseEntity.ok(ApiResponse.success(userMapper.toResponse(user)));
}

private String getCurrentKeycloakUserId() {
    Authentication auth = SecurityContextHolder.getContext().getAuthentication();
    Jwt jwt = (Jwt) auth.getPrincipal();
    return jwt.getSubject();  // Returns Keycloak user ID
}

7. ERROR HANDLING
Common Error Scenarios
1. Invalid Credentials (Login)
Request:
POST /api/auth/login
{
  "email": "user@example.com",
  "password": "WrongPassword"
}

Response:
{
  "success": false,
  "message": "Invalid credentials",
  "timestamp": "2024-01-01T10:00:00Z"
}

Status: 401 Unauthorized

2. Expired Token
Request:
GET /api/users/me
Authorization: Bearer <expired_token>

Response:
{
  "success": false,
  "message": "JWT token has expired",
  "timestamp": "2024-01-01T10:00:00Z"
}

Status: 401 Unauthorized
Client should: Refresh token or redirect to login

3. Invalid Token Signature
Request:
GET /api/users/me
Authorization: Bearer <tampered_token>

Response:
{
  "success": false,
  "message": "Invalid JWT signature",
  "timestamp": "2024-01-01T10:00:00Z"
}

Status: 401 Unauthorized

4. Missing Authorization Header
Request:
GET /api/users/me

Response:
{
  "success": false,
  "message": "Full authentication is required to access this resource",
  "timestamp": "2024-01-01T10:00:00Z"
}

Status: 401 Unauthorized

5. Insufficient Permissions
Request:
GET /api/users
Authorization: Bearer <customer_token>

Response:
{
  "success": false,
  "message": "Access denied",
  "timestamp": "2024-01-01T10:00:00Z"
}

Status: 403 Forbidden
Reason: Endpoint requires ADMIN role, user has CUSTOMER role

6. Refresh Token Expired
Request:
POST /api/auth/refresh
{
  "refreshToken": "<expired_refresh_token>"
}

Response:
{
  "success": false,
  "message": "Refresh token has expired",
  "timestamp": "2024-01-01T10:00:00Z"
}

Status: 401 Unauthorized
Client should: Redirect to login page

7. User Already Exists (Registration)
Request:

8. SECURITY BEST PRACTICES
✅ Implemented
HTTPS Only in Production


All tokens transmitted over HTTPS
Prevents man-in-the-middle attacks
Short Access Token Lifetime


Default: 5 minutes
Reduces window for token theft
Secure Token Storage


Frontend: Store in memory or httpOnly cookies
Never in localStorage for production
JWT Signature Verification


RSA256 algorithm
Public/private key pair
CORS Configuration


Whitelist allowed origins
Prevent unauthorized cross-origin requests
Role-Based Access Control


Use @PreAuthorize annotations
Check roles in JWT
Password Validation


Min 8 characters
Must contain uppercase, lowercase, number
Stored as hash in Keycloak
Stateless Authentication


No server-side sessions
Horizontal scaling friendly

9. TESTING AUTHENTICATION
Using cURL
# 1. Register
curl -X POST http://localhost:8081/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "Test123!",
    "fullName": "Test User",
    "phone": "0912345678"
  }'

# 2. Login
curl -X POST http://localhost:8081/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "Test123!"
  }'

# Save access token
TOKEN="eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9..."

# 3. Access protected endpoint
curl -X GET http://localhost:8081/api/users/me \
  -H "Authorization: Bearer $TOKEN"

# 4. Refresh token
REFRESH_TOKEN="eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9..."

curl -X POST http://localhost:8081/api/auth/refresh \
  -H "Content-Type: application/json" \
  -d "{\"refreshToken\": \"$REFRESH_TOKEN\"}"

# 5. Logout
curl -X POST http://localhost:8081/api/auth/logout \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d "{\"refreshToken\": \"$REFRESH_TOKEN\"}"

📝 SUMMARY
Authentication Flow Overview
┌──────────────┐
│ Registration │ → Create in Keycloak → Save to PostgreSQL
└──────────────┘

┌──────────────┐
│    Login     │ → Validate credentials → Return JWT tokens
└──────────────┘

┌──────────────┐
│ API Request  │ → Validate JWT → Extract user → Execute
└──────────────┘

┌──────────────┐
│   Refresh    │ → Validate refresh token → Issue new tokens
└──────────────┘

┌──────────────┐
│   Logout     │ → Revoke tokens → Clear session
└──────────────┘

Key Points
Keycloak handles authentication & token generation
User Service stores user data & business logic
JWT contains user ID & roles
Spring Security validates tokens automatically
Refresh tokens extend session without re-login
Stateless architecture for scalability
